## REA-SERVICE-SCAFFOLD-01 handover

Source-only scaffold for the standalone REA service. No install, no unit, no
deploy, no edge route and no admission was performed by this story.

Delivered in PR #1: `server.js` plus `api/service.js` (readiness and splash
only, every other path 404), the two `.datasquiz` contract files,
`deployment/operations.json`, the non-root Script 0-4 set, `docs/rea-service.md`
and the service suite under `tests/service/`, owned by the additive `service`
project in `scripts/lib/test-projects.mjs` and `vitest.config.ts`.

Delivered in this round (bootstrap defect): the deploy pin is one exact service
release commit recorded in `.datasquiz/service-identity.json` and read by
scripts 2 and 3 through `readReleasePin`, so the checkout and the environment
cannot drift apart; script 2 refuses a release whose tree lacks `server.js`,
`tests/service` or the packaged identity, then records the deployed commit in
that release identity; script 3 refuses a release that records a different
commit before writing the environment. The tracked pin is
`b9d20a3b678881089a8adf6c75ff2dfb0695a6f7` (the PR #1 merge), the upstream base
`c3647ade1e557c4179a8b825a37e0c2193cd2526` is recorded beside it, and the
package stays at 6.8.0.

Readback evidence in the handover comment: the service suite baseline tap, three
kill mutations, and the loopback `/health` `/` `/mcp` status codes.
