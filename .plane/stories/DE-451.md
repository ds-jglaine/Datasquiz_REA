## REA-SERVICE-SCAFFOLD-01 handover

Re-targets the already-merged non-root service wrapper from the superseded
placement to the AI stack. No install, unit, edge route, admission or deployment
is performed by this story.

Delivered on `rea-service-ai-stack-01`:

- `api/service.js` and `api/service.d.ts` default to the AI-stack runtime root and
  refuse every other root, including a subdirectory of it, so the service cannot
  claim a second tree.
- `.datasquiz/service-identity.json`, `deployment/operations.json` and
  `.datasquiz/documentation.json` name `/mnt/ai/rea`, `rea.ai.datasquiz.net`,
  scope `ai_node`, transport `stdio` and the Dev page `/platform/rea-service/`.
  The documentation manifest now carries the `ds-public-docs/v1` schema and an
  explicit `publicDocs` list, which the publication hook requires.
- Scripts 0-4 accept only the AI-stack root. Script 4 keeps the direct path for a
  host node that satisfies the packaged engines floor and otherwise runs `npm ci`
  plus `npm run test:service` in the pinned `node:22-alpine` image by digest
  (`sha256:fe4f6d74e20370acb04ad889077d14d0f64a9c8ea6a42bc60cddf1e844699914`,
  node `22.23.4`), so a release test cannot fail on `EBADENGINE`. The container
  maps the invoking uid/gid, installs git and bash inside the ephemeral image
  for the pin and script assertions, and mounts only the deployed release.
- Both service test files re-target the contracts and add a path guard over
  `api/`, `deployment/`, `.datasquiz/`, `scripts/`, `docs/rea-service.md`,
  `tests/service/` and this story file's handover prose. The accepted brief
  quoted below names the superseded placement to explain the re-target, so the
  guard checks the prose outside that quotation.
- The deploy pin is the exact 40 character re-target commit `<PIN>`, shared by
  scripts 2 and 3 through `readReleasePin`; the pin's tree carries
  `api/service.js` with the AI-stack default, `server.js` and both service tests.

Gate evidence (commands actually run in the isolated gpu2 worktree at
`/mnt/ai/source/work/rea-service-ai-stack-01`, container image digest
`sha256:fe4f6d74e20370acb04ad889077d14d0f64a9c8ea6a42bc60cddf1e844699914`):

- RED before the change and GREEN at the candidate head for
  `npx vitest run tests/service`, recorded beside the path-guard red log.
- `bash -n` over scripts 0-4.
- Loopback `GET /health` 200 with the pinned commit and `/mnt/ai/rea`,
  `GET /` 200, `GET /mcp` 404.
- Script 0 `--dry-run` lists only `/mnt/ai/rea` targets.
- One kill mutation per acceptance criterion, each with its failing tap log.
- `git ls-tree`/`git show` at the pin proves the re-target is in the pinned tree.
